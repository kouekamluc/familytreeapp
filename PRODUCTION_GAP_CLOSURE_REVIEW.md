# Kkevo Family: workflow closure and release review

5 October 2026. Scope: the existing Android experience and its API. Keep the Kkevo Family name, Eban branding and current green interface. No separate browser redesign, public feed, chat, DNA matching or speculative ancestry features were added.

**Release verdict: not ready for a public production launch yet.** The local account/family workflows have been substantially completed and tested. Missing release infrastructure, reviewed policies, actual account erasure and operational/device evidence are still blockers. The user confirmed that no HTTPS domain, support email, mail provider or reviewed privacy/deletion rules exist yet. Local tests cannot supply those inputs.

This review is the current implementation record; the original findings in PRODUCTION_FINISHING_PLAN.md are the planning baseline, not a description of today's code.

## Verification

- PostgreSQL: **103 tests passed**, no skips, including transaction/permission/recovery coverage. `.dev-logs/final-release-postgres-tests.log` records the isolated test database being destroyed and the clean system check. No production database was migrated.
- Mobile regression suite: **79 tests passed**, including import count preview/cancellation, profile/story conflict recovery, relative/connection draft restoration, account/server isolation and 200% phone text. `flutter_frontend/build/final-release-tests.log`. Final Flutter analysis reports **no issues** in `flutter_frontend/build/final-release-analysis.log`. Django checks pass and `makemigrations --check --dry-run` reports no changes.
- Native Android: **all seven journeys passed together** on the existing API 35 virtual phone. This includes the original account/family journeys, story conflict review preserving another editor’s unrelated changes, content report receipts, real UTF-8 file save/open, cancellation, share chooser and exact synthetic gallery image selection followed by upload. `.dev-logs/final-release-native.log` records the successful combined run and subsequent normal-app build/install. The final focused host completion check also passed: `flutter_frontend/build/native-handoff-check.log`, with seven checked system actions and no errors in `build/pc-test-results/native-system-result.json`.
- Read-only release audit: eight development/missing-configuration checks blocked; effective private boundary and applied isolated migrations passed. `.dev-logs/release-configuration-audit.log`. Passing configuration checks only proves basic setup shape, not successful DNS, SMTP delivery or hosting security.

The verified normal interactive APK was restored after the focused check. `.dev-logs/final-release-install.log` records successful installation/start; `release-installed-welcome.png` captures the app. Foreground package/activity and installed version **1.0.0+1**, min SDK 24 / target SDK 36, were inspected through Android. This is the audit debug app, not a signed production release.

The virtual phone is the existing Pixel 5 / Android 15 API 35 emulator, `familytree_pc_test_api35`. Native builds use `com.kkevo.familytree.audit`, local port 18000 and `.device-test` records/media/mail. Five-second test access tokens exercise renewal. Test messages stay in the isolated file mailbox. No real invitations or emails were sent.

Earlier attempts exposed harness problems: identical ancestor names from previous runs filled the ten-result suggestion limit, and Flutter PixelCopy could not capture its covered surface behind an Android activity. Fixtures now use unique names; native checks capture the actual Android window and inspect its UI. The photo fixture receives a fresh timestamp so the picker selects that exact image; byte equality catches accidental selection of a screenshot. The host callback checks all seven native system actions and cleans up its monitor before the test framework exits. Failed attempts were not counted as verification. The file test creates a uniquely named synthetic JSON document, and the image test selects a synthetic Eban asset rather than a real person's photo.

## Data and upgrade boundary

Deploy the matching API/migrations with the app. New family migrations: **0007** backfills the normalized search index and **0008** stores content review receipts. Earlier family 0005–0006 and users 0005–0007 remain required. Review the account collision and credential migration notes before applying to real data.

Backup format is now **8.0**, includes reports and restores the normalized names for older compatible backups. Readers accept versions 4–8, with missing legacy report sections treated as empty. Local backup tests verify report roundtrip and older search-name rebuilding. This is not an off-device operational restore rehearsal.

Legacy public flags are not silently rewritten. Their read access is blocked by the current server configuration. Auditing/communicating historical exposure and selecting final visibility rules remain operator work.

Portrait links are short-lived signed bearer URLs; raw media paths must remain private in deployment. An already-issued link can remain usable until expiry. Graph caches remain in app-private preferences, scoped by server/account; the protected draft/credential vault is not a claim of end-to-end family-data encryption. JSON transfer excludes image files and is not a full media backup.
